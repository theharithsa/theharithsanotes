# Search overlay and Blog controls — 1.17.0

Issues #60 and #61 replace the crowded masthead and route-changing search interaction. Blog keeps its title/intro above the archive; a compact native tag selector sits beside topic controls below it. Tags still combine with topics, retain existing public tag/topic URLs, update archive visibility/counts, reject unknown initial labels and reset correctly. On phones, controls stack as labeled dropdowns. No article/tag data is renamed or removed.

The header search button and Ctrl/Cmd+K open one native modal dialog without changing the current URL. The panel blurs the background and uses short open/close/reveal animations. Input receives focus; the browser provides modal inertness/focus containment; Arrow keys traverse suggestions, Enter opens a result, Escape/outside/close return focus. Another open editor/dialog is not displaced. Reduced-motion disables decorative animation. Existing /search bookmarks open the same component automatically; the old full-page form/hero is removed. Search scopes and current API pagination remain available in the scrollable result list.

SearchSession debounces 180ms, aborts the old request, enforces latest-request ownership and times out a request after 15s. Close, hidden-page, reader-preference change and page navigation clear results/terms; Back restoration stays empty. Reopening cannot receive a late previous response. Loading/error/empty/retry states remain distinct, and typed queries use bounded no-store JSON POSTs rather than URLs/storage. Results use textContent and validated same-origin links. A changed authorization boundary during pagination restarts from offset zero, clearing previous results before any append. A lost private scope falls back to a fresh public search. Server invitation checks, request-local restricted indexing, capacity/rate limits and public-only cache remain unchanged.

The overlay carries data-dtrum-mask and data-dt-mask, covering its terms, text and link attributes. Existing Session Replay disable-on-load remains intact. See [Dynatrace capture masking](https://docs.dynatrace.com/docs/observe/digital-experience/session-replay-latest/configure-session-replay-web/configure-session-replay/url-exclusion-and-masking). Before opening, the controller switches the public document's native view-transition rule to none. It restores the rule only after content is cleared/closed, and leaves it off during outgoing navigation. No private snapshot/payload cache is created. Native modal behavior follows [MDN dialog guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

The new generic sr-only utility keeps accessible labels/headings off the visible canvas; original article-list validation now scopes its extraction at the actual article-end marker rather than counting a new modal list as article content. The search state class uses standard field assignment so the Node strip-types test runner can import it. These were caught and corrected during local checks.

Local check/build and 59 site tests pass, including five request lifecycle/privacy regressions and two Blog/modal contract checks. Chrome local server-mode checks use only static public index data: SalesDrone gives 2 suggestions, ArrowDown focuses a result, close/Escape clear state and restore focus, Ctrl+K opens, backdrop blur is 14px and the 390px panel fits without overflow. Static-mode local development intentionally lacks runtime API routes; its error/retry state was checked separately before server-mode successful requests. The concurrent 1.16.2 Meet Vish reading-flow correction is merged and preserved. Final hosted current-source CI, immutable provider receipts, responsive screenshots and Dynatrace evidence are tracked in the linked PR.

No API/schema/rules, content, author profile, footer, frozen Margin 1.0.0 or template 1.9.0 changes. Rollback uses matching private-aware 1.16.2 runtime/client assets and preserves all data, drafts, media and audit records.
