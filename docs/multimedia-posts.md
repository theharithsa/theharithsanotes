# Multimedia posts — 1.22.0 / issue 80

Workspace's story editor now supports responsive media blocks in Blog, Books, Projects, Podcasts, Entertainment, GoGs, Journal, People and Meet Vish. Existing structured fields remain available; the additional rich story is optional on previously structured collections and does not replace existing content automatically. All new content follows the same draft, revision and Publish workflow. No existing entries are edited or republished by this release.

Paste a supported link by itself on an empty line, or choose **Embed media** and insert it in the inline panel. Supported providers are YouTube (watch, short, live, share and embed links), Vimeo (including an unlisted hash), Spotify tracks/albums/playlists/episodes/shows, and HTTPS MP4/WebM/MP3/M4A/Ogg links. Inline links in prose remain links. Select a media block to replace it using the panel, drag to move it, or delete it using the editor selection. Text below the block can serve as a caption. Players preserve their aspect ratio, expose native controls/fullscreen where supported and include an ordinary source link. Autoplay is never enabled by the site. A provider can still restrict playback or embedding.

**Upload video/audio** accepts MP4/WebM video and MP3/M4A/Ogg audio up to 24 MiB. Original bytes and embedded file metadata are retained; there is no transcoding. Use a hosted provider for larger videos. Existing JPEG/PNG/WebP image uploads retain their 8 MiB / 40 MP limits, stripped metadata and responsive variants. File signatures choose content type, with nosniff on downloads. Invalid containers or unsupported codecs may not play in a visitor's browser. Signed media responses support a single byte Range for seeking. Private-media authorization runs before range/length responses; Journal and People still require an active invitation and a published reference. No private media moves to the public bucket. Source URLs are not sent to telemetry; existing bounded upload/read/publish events and OTel spans cover the journey.

API clients use the same scoped `POST /api/v1/media` multipart endpoint, then use its returned URL in an HTML video/audio block. The optional `html` story field is now explicit in Books/Projects/Podcasts/Entertainment schemas. Standalone supported URL paragraphs are normalized by the shared sanitizer, so API/import content and the editor agree. Raw iframe markup is accepted only for the exact supported player providers and rewritten to canonical URLs and attributes. Scripts, srcdoc, events, autoplay and arbitrary iframe origins are removed. No generic URL preview fetch or server-side oEmbed request is introduced. OpenAPI and the existing Swagger portal describe file types, limits and variants.

The shared provider mapper follows [YouTube's embed format](https://developers.google.com/youtube/player_parameters), [Vimeo's player URL format](https://developer.vimeo.com/player/sdk/basics) and [Spotify embeds](https://developer.spotify.com/documentation/embeds). The editor uses the installed Tiptap 3.33.0 [node paste rules](https://tiptap.dev/docs/editor/api/paste-rules). No new package is required.

Workspace helper/status text uses contained, spaced notices. The redundant ready-state invitation sentence is removed; actual authentication errors and invitation outcomes remain announced through the existing status region. Empty notices disappear. Long card instructions wrap within a readable width.

Verification covers provider/URL attacks, standalone versus inline links, sanitizer idempotence, upload type/range boundaries, private draft/publication/anonymous access, actual editor paste/round-trip/panel interaction, responsive players and notices. CI runs the existing CMS emulators, auth/security and content suites. Release uses immutable preview then live images and matching Hosting assets. Rollback uses 1.21.1's image and Hosting pair; older code safely strips new embed nodes but does not delete stored drafts or uploaded objects. Final provider/browser/transport receipts belong in the issue-linked PR; transport acceptance is distinct from searchable Dynatrace evidence.
